# Outcome

When an agent connects to `/mcp`, the server instructions now describe the project: first the author's paragraph from the new `instructions` option, then the kinds of records and the one-record operations for each, built from the catalog. The generated part is sent even when search is off. The instructions, tool descriptions, search-off message and sign-in page name no technology, and a test fails if Keystone, GraphQL, Prisma or keystone-mcp comes back. Landed in `c6eebea`.

The generated part uses the app's own list names. In the shop example the people are "users", and the author's paragraph says that users are the customers and the admins. The coordinator accepted this instead of renaming the example's `User` list, which also holds admins. Error text and codes from a failed call still match the app's own API, and the server still reports its name as `keystone-mcp`.
